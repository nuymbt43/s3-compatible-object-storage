## 流量方向容易搞反：上传不花钱，雨云发给你才花

雨云的流量只算一个方向，而且这个方向的命名和不少人的直觉相反。所谓“上行流量”，指雨云把文件发给你，也就是用户下载、浏览器拉取、CDN 回源这类动作；“下行”指你往桶里上传文件，不计费。做图床的人上传一次，之后每次被访问扣的都是“出去”的那份配额。

如果你的云服务器和对象存储在同一个区域，用内网地址互访，上行下行都不计入流量。买一台宁波的云服务器再配一个宁波的 ROS 实例，两边同步数据不花流量费。这条对静态资源就近部署的站点最实用。

## “S3 兼容”到底兼容什么：四项设置和八个测试

S3 兼容指服务商实现了与 Amazon S3 相同的 REST API：bucket、object、key、带签名的 HTTPS 请求。你为 AWS 写的工具——AWS CLI、boto3、rclone、s3cmd——改掉 endpoint 和密钥就能用。每次调用都是发往 endpoint 的 HTTPS 请求，SDK 用 SigV4 以私钥签名，服务端验签后在自家后端执行，返回 S3 客户端期望的响应格式。

从 AWS 迁过来，通常只需要改四个地方：endpoint URL、access keys、signing region、addressing style。

核心调用（put、get、list、delete）在绝大多数兼容服务上表现一致。版本控制、Object Lock、生命周期规则、桶策略这些，各家实现程度不同，有的缺失，有的只做了一部分。访问控制模型差异最大：AWS 靠 IAM 策略、桶策略、ACL 三套组合，不少厂商用自己的权限体系。加密方案也是，AWS 有 SSE-S3、SSE-KMS、SSE-C 三种，兼容厂商常常只有一种。

### 两个最容易踩的坑

**寻址风格。** AWS 默认 virtual-hosted style，bucket 名放在主机名里；很多兼容厂商要求 path-style，bucket 放在 URL 路径里，形如 `endpoint/bucket/key`。boto3 用 `addressing_style` 参数，JavaScript SDK 用 `forcePathStyle`，Go SDK 用 `UsePathStyle`。rclone 的 S3 后端默认就走 path-style。AWS 自己表示 path-style URL 未来会停用，所以从 AWS 往兼容服务迁的时候，这一项经常需要显式打开。

**上传 checksum。** 较新的 AWS SDK 和 CLI 默认给上传加 checksum，并可能用 aws-chunked 编码发 body，部分兼容端点会直接拒绝，报 `MissingContentLength` 之类的错误。把客户端的“请求 checksum 计算”改成“when required”通常能解决。

### 迁移前在测试桶里跑这八项

1. **寻址风格**：厂商需要时开启 path-style，确认 list、put、get 都正常。
2. **签名与 region**：确认 SigV4 可用，找到厂商期望的 region 字符串。region 填错通常表现为授权错误，不是 404，容易误判成密钥问题。
3. **默认 checksum**：用当前版本的 SDK 上传一个小文件，失败就把请求 checksum 计算设为“when required”再试。
4. **大文件**：传一个超过 SDK 分片阈值的文件（boto3 默认 8MB），确认分片上传能完整走完，不只是小文件能传。
5. **预签名 URL**：生成一个，在浏览器里打开，确认能正常访问。
6. **依赖的功能**：把应用调用到的 AWS 功能列全——版本控制、生命周期规则、事件通知、对象标签、跨区域复制——逐项对厂商文档。
7. **复制后完整性**：用 `rclone check` 比对源和目的的大小与哈希，别只看文件数量对得上。
8. **速率限制**：问清楚请求上限，拿最忙的那个任务压一遍。

这八项跑完，你保留的是原有的脚本、SDK 和备份工具，以后换厂商也不用重写代码。

关于雨云 ROS 具体支持哪些 S3 功能，官方没有公开一份完整的兼容性矩阵。一个第三方 Go SDK 把 bucket 生命周期、桶策略、CORS、文件外链 URL 都封装成了接口，说明这些能力至少在管理 API 层面存在；版本控制、Object Lock、事件通知在现有资料里没有对应条目，不能假设它们可用。真要依赖这些功能，按上面第 6 项逐条测，别按“兼容 S3”四个字推断。

## 兼容程度能差到什么地步：三个例证

同一家厂商的不同区域，功能都能不一样。OVHcloud 的官方兼容性文档把 Regional 和 Local Zones 分开列：Intelligent tiering、Object ownership、SSE-KMS、事件通知、bucket metrics/analytics/inventory 全部不支持；object tagging、copy object、Object Lock 的 legal hold 和 retention、replication、server access logging 只在 Regional 支持；put bucket policy 反过来只在 Local Zones 支持。同一个产品名，换个区域就是另一套能力。

有些限制来自 S3 API 规范本身。Commvault 的文档写得很直白：S3 API 规范没有提供查询总容量或可用容量的接口，所以对接任何 S3 兼容存储时都读不到 Capacity、Free Space、Usable Free Space。这不是某家厂商偷懒，是协议里就没有这个能力。

还有“协议层兼容”和“功能层兼容”的区别。RustFS 声称 100% 兼容 S3 API，但没实现 MinIO 的 `mc admin` 子命令、LDAP 集成和 Object Lock。它的 handler 严格遵循 `PUT /{bucket}/{key}` 的 header 规格，`GET /{bucket}?list-type=2` 返回符合 `ListBucketResult` Schema 的 XML，所以 boto3、aws-sdk-java 都能接；但管理层面的东西不在 S3 协议里，自然也没有。

这三件事放在一起说明同一个道理：能连上，和能用上你需要的那个功能，是两道关。

## 谁适合，谁要先等等

适合的：图床和博客图床（Chevereto、Lsky Pro 这类程序直接对接）、站点静态资源、备份归档、CI 构建产物、软件安装包分发。这些场景的共同点是用量能预估，且不需要对象存储承担数据库职责。

## 常见问题

**rclone、s3cmd 能直接连吗？**
能，改 endpoint、access key、secret key、region 四项。rclone 默认用 path-style，多数兼容服务不需要额外配置；如果连不上，先检查 region 字符串是不是厂商要求的那个。

**上传文件要钱吗？**
不要。只有雨云把文件发给你才算流量。你往桶里传多少都不计费。

**流量超了会直接扣钱吗？**
不会。默认停服，需要你手动在控制台开启弹性计费，之后按十堰 0.2 元/GB 或宁波 0.1 元/GB 计流量费。不想被扣就别开。

**7 天无理由怎么退？**

**10 元档能干什么？**
